# SkriptumScheduling — standalone R09 domain wave

This Foundation/CryptoKit module supplies persistent scheduling intent, recurrence, budget and run/proposal contracts. It issues no network/provider calls, activates no native task and is not a deployed scheduler. Full R09 remains open under [the scheduling plan](../../docs/SCHEDULED_TASKS_PLAN.md).

## Implemented APIs

- `ScheduledTask` and `SchedulingScope`: account/library/Space/page identity, bounded prompt/block scope, generation and lifecycle. `SchedulingStore.add` accepts only initial draft intent; activation requires a supplied current execution grant. Grant construction is not authentication: a future backend must verify identity, inherited roles and revocation before providing it.
- `ScheduleRule.next(after:)`: one-shot and daily/weekly Gregorian recurrence with IANA timezone, next-valid DST gap and first-only overlap. Due catch-up keeps latest eligible occurrence; IDs include task generation and UTC instant, preventing duplicate enqueue after restart.
- `BudgetLedger`: checked integer money/token bounds, canonical UTC month, expiring/versioned quotes, persisted account/currency monthly ceiling enrolled from owner grant, and per-task monthly ceiling. Holds, settlement and release are idempotent. Uncertain dispatch retains funds; account usage spans libraries/Spaces. Enrolled ceilings cannot silently change via another task. No published price or billing authority is invented.
- `RunStateMachine` and `SchedulingStore`: CAS-versioned actor transactions, fenced bounded leases, legal transitions, fresh grants at authorization/dispatch/result publication, quote recheck at dispatch, and generation cancellation. Reclaim must use a fence never used by that run; all used fences are persisted and bounded by the three-attempt limit. Decode checks history size/attempts/current-lease consistency. `recoverExpired` marks expired post-dispatch work uncertain; `settle` reconciles cost. Cancellation preserves already settled cost and unresolved uncertain holds. Internal idempotent state does not promise exactly-once external AI calls.
- `ScheduledProposal`: bounded block replacements, immutable scope/page/base revision/allowed IDs and SHA256 of exact UTF8 source. Admission rejects revised source, foreign resources and Unicode/CRLF normalization differences. No document mutation or acceptance receipt is implemented here.
- `SchedulingStore.snapshot` and `SchedulingPersistence`: immutable snapshots; validated candidate is synchronously persisted before actor state publication, avoiding actor-reentrancy CAS gaps. Local state is at most 32 MiB, 1,000 tasks, 10,000 runs and 1,000 proposals, with explicit prompt/source/output limits. Unknown or malformed state rejects initialization. This actor is process-local, not distributed authority or a multi-process file lock.
- `FileSchedulingPersistence`: component-wise descriptor traversal with `O_NOFOLLOW`, bounded 64 KiB incremental reads after regular-file validation, final `O_NONBLOCK` to reject FIFOs safely, private temporary file and `fsync`/descriptor-relative atomic rename. Existing symbolic ancestors/final links are rejected. Caller supplies an owned canonical path; private local files contain prompt/proposal content and must not be exported as secrets-free telemetry. No API key/OAuth token/vault credential is stored.

## Verification

```sh
swift test --package-path Modules/SkriptumScheduling --build-system native --disable-sandbox
```

Actual Swift 6.4/macOS 27 native SwiftPM suite: **20 tests in 3 suites pass**, including real atomic-file restart/write-permission failure, ancestor/final symlink rejection, owned temporary FIFO rejection, bounded/unknown schema load, concurrent final account reservation, overflow/decoded ledger corruption, source-byte digest, scope denial, DST behavior, persistence rollback/CAS, cancellation/late result, expired lease recovery, settled uncertain charge→cancellation→restart and immediate plus A→B→A historical-fence rejection across restart with unchanged disk/memory.

Root scratch evidence: `work/scheduling-red.log`, `scheduling-store-red.log`, `scheduling-review-red.log`, `scheduling-second-review-red.log` and final `scheduling-fence-history-green.log`. The second review RED reproduced cancellation rollback and immediate fence reuse (5 issues); `scheduling-fence-history-red.log` reproduced historical A→B→A reuse after restart (5 issues). A bounded FIFO RED instrumentation attempt did not reach the test because SwiftPM planning/helper environment failed; it is **not** claimed as an executed blocking proof. The original blocking-open flags were independently reviewed; the permanent owned FIFO test passes after `O_NONBLOCK`. Probe process groups/fixtures were cleaned. No unsafe external probe was used.

## Required following work

Pause/revise APIs and their generation semantics, persisted read-only summary results, missed-occurrence audit, monthly/end/count recurrence, separately authorized account-ceiling changes and explicit exhausted pre-dispatch retry policy remain absent. Proposal acceptance needs an atomic receipt committed WITH the owning document mutation in a reviewed Core integration; an after-apply receipt has an unacceptable crash window.

Native manager/storage binding, truthful server activation readback, conflict/revision proposal review, real server database/leased workers, authenticated role inheritance, vault/region selection, provider eligibility, uncertain-cost reconciliation authority, offline-device execution proof, cancellation/revocation races and opt-in notifications remain deployment/integration gates. Existing native ChatGPT/PCC credentials are not enrolled for unattended server use. Standalone tests do not close these gates or complete the professional app.
