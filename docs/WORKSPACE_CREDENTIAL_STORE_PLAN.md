# Workspace credential Keychain store

Module-only Security framework wave. Preserve App/Core/root Package/Xcode/server/signing configuration. Existing Foundation client and all cross-language tests stay compatible. Offline writing and device provider credentials remain separate.

A concrete `WorkspaceKeychainCredentialStore` actor is initialized with one explicit immutable profile ID and a dedicated service namespace. Its existing origin/account protocol methods therefore have an exact profile context; no enumeration, default account/profile, shared access group or global fallback. `WorkspaceCredential` adds optional profileID with default nil for existing HTTP fixtures/callers. Unbound credentials can be used for the existing explicitly supplied HTTP session API but can never be persisted by this store. Save requires the exact configured profile.

Keychain item identity is SHA-256 over length-prefixed canonical origin, exact bounded profile identifier and canonical account UUID. Store a private bounded schema1 record containing that exact scope and opaque session token, validate on every read, and return only a newly validated redacted WorkspaceCredential. No public credential Codable conformance. Generic-password items use `WhenUnlockedThisDeviceOnly`, synchronizable=false, data-protection Keychain and no shared access group. Update/add uses a bounded duplicate-item race retry; no delete/recreate gap or unrelated item deletion.

`errSecItemNotFound` returns nil on load and successful idempotent deletion. Other OSStatus codes throw typed redacted status error; malformed/oversized/wrong-scope record throws typed invalidRecord and remains untouched. Locked/unavailable storage never appears as missing and never falls back to a file/plaintext store. No authentication UI is invoked by load/update/remove; integration can present its own login/error flow. Actor serializes its own calls; Keychain handles other processes atomically.

## Final implementation and evidence

Concrete actor uses one explicit immutable ASCII profile ID (1–128 bytes), service namespace, hashed length-prefixed canonical origin/profile/account scope, private schema1 JSON record bounded to 2 KiB, and fresh no-prompt `LAContext.interactionNotAllowed` via `kSecUseAuthenticationContext` for each query. No deprecated authentication-UI constants or global contexts. Reads validate exact record keys, version, origin/profile/account/token and actual protected attributes; malformed data is retained. Save performs up to three update/add attempts only for the duplicate-item race, without a delete/recreate gap. Existing public `WorkspaceCredentialStore` protocol is unchanged; the actor's immutable profile supplies its explicit context. Optional credential profile defaults nil for compatibility, but nil/different profile saves fail before Keychain access.
