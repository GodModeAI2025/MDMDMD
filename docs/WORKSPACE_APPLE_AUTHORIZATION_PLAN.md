# Native Apple authorization broker

Scope: native AuthenticationServices proof acquisition for the reviewed Workspace identity client. This is separate from NativeChatGPTSignInCoordinator and AI provider credentials. No Apple capability, signing key, production service or successful Apple login is implied.

The caller supplies its own scene presentation anchor and a fresh WorkspaceIdentityChallenge from the configured identity client. The broker creates an Apple ID request with the exact returned nonce and state; it requests no name/email scopes because those values do not establish Workspace identity or permissions. The broker never chooses an application-global window or account.

One broker instance admits one request at a time. A controller identity and unique attempt generation fence every delegate callback. Cancellation resumes the continuation once, calls the documented controller cancel method, clears retained proof/request state and prevents a callback from completing a later request. Task cancellation uses a MainActor hop scoped to that exact attempt; it cannot cancel an unrelated new request. A bounded timeout is at most the remaining challenge lifetime. Detached/deallocated presentation scenes cancel their owning request.

Success requires an Apple ID credential, returned state exactly matching the requested UTF8 bytes, nonempty bounded identity-token and authorization-code Data, strict UTF8 decoding and the existing WorkspaceIdentityProof input validation. The broker does not parse or trust JWT issuer/subject/role/email claims. The configured server verifies signatures and independently redeemed identity; acquisition alone creates no account, credential-store entry or library binding.

Errors are a small controlled enum (busy, cancelled, expired, invalid response, unavailable); underlying provider error text and credential payloads never enter logs. Returned proof retains its existing redacted non-Codable representation. On cancellation or failure the UI preserves local drafts and describes any server-side uncertainty separately; native proof cancellation is not evidence of remote session revocation.

Implementation owns a new file under Sources/SkriptumAuth and focused tests under Tests/SkriptumAuthTests. Root package Auth depends explicitly on WorkspaceClient; the Xcode app already compiles both source directories. Tests first cover exact state, malformed UTF8 and byte boundaries, once-only completion and old-attempt cancellation/callback rejection. Generic SDK compilation and simulator delegate/error behavior are separate from actual Apple authorization. The latter requires the enabled App ID capability, production audience/origin/vault and a real eligible account/device.

API evidence: inspected the installed iOS27 AuthenticationServices SDK headers ASAuthorizationController.h and ASAuthorizationOpenIDRequest.h on 2026-10-09. They expose request nonce/state, weak controller delegates/presentation provider, performRequests and cancel (available since iOS16). The existing native ChatGPT coordinator supplies the repository's MainActor/scene-anchor/cancellation convention; it is not reused as an Apple ID token exchange.
