# Persistent scheduling domain — verified implementation subset

The standalone Modules/SkriptumScheduling package implements validated persistent intent, one-shot/daily/weekly time rules, CAS actor transactions, account/task budget reservations, expiring grants, cancellation, cost reconciliation, uncertain-dispatch recovery and exact-source proposals. It performs no provider calls and is not linked into the native application.

Twenty permanent tests passed both in the implementation run and an independent run. The final reviewed Swift tree SHA256 is `d9e11ab69227c0b7dea509fd12f87b13f15412993076bceb8a6a895e19322494` (sorted module-relative Swift paths, NUL, bytes, NUL; excluding .build). REVIEW.md records the final scoped verdict. Regression rounds reproduced permission/budget admission defects, cancellation of settled uncertain runs, and reused worker fences, including A → B → A after restart. Final source retains all used fences under the three-attempt limit. FIFO rejection is verified after the fix; the bounded pre-fix instrumentation did not reach the test and is not counted as an executed blocking proof.

Required next work remains pause/revision semantics, read-only summaries, missed-occurrence records, extended recurrence, atomic document-plus-acceptance receipts, native management, authenticated server/database/worker deployment, provider enrollment and actual offline-device execution. Tests prove the implemented domain contracts, not server authorization or complete R09. The full professional application and TestFlight acceptance remain open.
