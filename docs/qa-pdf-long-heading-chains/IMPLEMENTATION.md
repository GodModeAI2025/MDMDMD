# Page-spanning PDF heading chains

The previous complete-chain reservation rejected otherwise valid manuscripts when an adjacent heading chain plus its body prefix exceeded one page. The failure was reproduced with 30 text headings followed by ordinary text or fenced code: itemExceedsPage, before any complete PDF could be returned.

The semantic traversal now collects each text-only chain once, preserving heading indices, destinations, font attributes and structure roles. The writer measures each complete heading once and builds forward page-sized groups. Only the final group additionally reserves the first three body lines. Each group is admitted before drawing; complete headings remain intact, and the last heading stays with its body prefix. Short chains still remain together. Heading-only chains use the same partition with no body reservation. Cancellation and the existing page limit remain in force; failed writes still cannot return partial output. The obsolete cumulative lookahead parameter/cache were removed.

The first backward-grouping candidate produced four pages, with a short first group and a spilled body. Forward grouping instead produces three pages for both final fixtures: headings 1-14, 15-28, then 29-30 and the complete ten-line body. This avoids the extra page without changing source text, spacing or fonts.

Evidence: all 100 export tests pass, including short three-heading chains, adjacent heading/paragraph promotion, tagged heading roles/order, chapter destinations and code-first endnotes. Final unsigned generic iOS Simulator Debug app compilation passes with terminal exit 0 / BUILD SUCCEEDED (work/pdf-long-heading-compile.log). Independent strict pypdf reads both final outputs without warnings, finds all 30 headings exactly once in order and all 10 foxes, and places heading 30 and the first body line on page 3. All three pages of both outputs were rasterized with Poppler and visually inspected: no clipped or overlapping content.

Limits: an individual heading too tall to share a page with its required follower prefix remains an explicit geometry error; splitting inside such a heading needs a separate policy. Mixed inline-image headings, non-text followers, title reservation, all-theme/resource/accessibility and actual native app export acceptance remain open. The app's semantic route remains Debug QA opt-in; Release retains WebKit. Pending user decisions about the obsolete Xcode dialog and CloudKit/Push capability access remain unchanged; no new permission action, signed archive, upload or TestFlight delivery occurred. R01-R15 remain binding.
