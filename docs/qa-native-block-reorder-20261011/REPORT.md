# Native SwiftUI27 block reordering — 2026-10-11

The old block grip was also a Menu and carried a standalone UUID string drag, with individual string drop targets. Reordering now uses SwiftUI27 ForEach.reorderable and a native reorderContainer, giving the system ownership of drag placement/gaps. A separate44pt grip routes draggable(containerItemID:) to that container; the adjacent block menu retains move-up/down alternatives. No custom gesture changes or text-selection gestures were added.

BlockEditing.reordering validates unique local document/source identities, rejects empty/duplicate/missing sources and missing/self destinations, keeps multiple dragged blocks in their existing document order, and supports moving to the end. Unchanged order is not committed. The reorder callback reads current blocks and publishes the result through the existing accepted-proposal callback only after success. Existing Markdown boundary separation is applied when moving an unterminated block before another block; this can add separators, not erase source content.

Two added tests verify exact Unicode/CRLF bytes for separated blocks and stable identity, invalid and no-op requests, then actual image block movement, binary image preservation, durable reopen and stale-revision rejection without snapshot mutation.
