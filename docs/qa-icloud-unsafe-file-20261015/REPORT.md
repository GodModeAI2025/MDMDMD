# Build 11 iCloud Outbox.unsafeFile

15 October 2026. Actual TestFlight feedback `AGaFS_uUsisRBoGO5SREx1k`, submitted 08:51 CEST, iOS 1.0.1 (11), iPhone 17 Pro Max / iOS 27.2. The screenshot and owner-supplied diagnostic both show `Outbox.unsafeFile`, with zero captured counts. This is a new direct local-storage failure, distinct from earlier account-access screenshots. In the actual connect implementation, account lookup succeeds before the outbox is constructed. No new account sign-in is requested.

## Reproduction and correction

Foundation on the current Mac host preserves the known `/tmp` system alias even after `resolvingSymlinksInPath()`. `lstat` confirms it is a symbolic link; POSIX `realpath` returns `/private/tmp` (and `/var` resolves to `/private/var`). An isolated fixture with an initially absent `Library/Application Support` suffix reproduces both the physical-path mismatch and the exact `ICloudSyncJournalError.unsafeFile` with the old implementation. The red log is retained. This proves the alias/strict-walker failure contract locally; it does not establish the exact failing syscall on the reporter's physical phone.

Apple's [NSURL path-resolution reference](https://developer.apple.com/documentation/foundation/nsurl/resolvingsymlinksinpath) documents normalization of the `/private` prefix. This is a mismatch between Foundation path normalization and our strict POSIX no-follow traversal; it is not presented as a new Apple OS defect. Only the Foundation-provided document and support roots are now canonicalized with POSIX `realpath`. When a suffix does not yet exist, the existing system ancestor is canonicalized and the missing components are appended. This creates no directory by itself and changes no stored bytes or selections. Other IO failures retain the existing fail-closed behavior. Production call sites remain the two zero-argument system-root properties. No imported/library/interior user URL is sent through this helper.

All original descriptor-bound no-follow, ownership, file mode, link-count and atomic-write checks remain unchanged. A new regression confirms that a linked interior ICloudSync directory is still denied and that the external target's exact bytes remain unchanged. The roundtrip fixture confirms exact queued Unicode/CRLF payload, reopen and journal bytes. All 22 targeted root/session/outbox tests pass. The full root run also passes: 806 actually executed tests, four optional cases skipped, zero failures. The official Xcode RunCodeSnippet also executes the actual production helper in a Previews-managed iOS27.0 simulator app process (PID99657, bundle com.mobilebox.Skriptum, old bundle label11 with the new source). The Foundation-only alias-plus-missing-suffix fixture throws unsafeFile; the actual production helper resolves it and the real journal reopens one exact41-byte Unicode/CRLF payload with its unchanged revision. Normal simulator system roots and ancestor traversal already work, so the earlier hypothesis of global-ancestor sandbox denial is not reproduced. This is a runtime fixture, not proof of the physical iPhone27.2 path or live CloudKit transfer. Both official Xcode MCP SDK builds pass: iOS arm64 1.0.1 (12) and native macOS 1.0.1 (14). Actual Info.plist metadata and build receipts are retained.
