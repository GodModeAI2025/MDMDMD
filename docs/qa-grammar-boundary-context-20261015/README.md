## Reproduced problem and correction

The previous whitespace-only fallback split `an test` between two requests, so the actual native engine's `EN_A_VS_AN` finding disappeared. `baseline.log` first reproduces that failure in a controlled engine fixture. `native-baseline.stderr` then reproduces it with the real pinned native engine and old source from commit 823940440deb18df9a795f0690513ec49089db70: the full-input reference returns one finding at the original marker, while the chunked reviewer returns zero and exits 1. Nothing is removed from the failing fixture.

Both the bundled-native reviewer and the explicitly selected own-server client now use the same review-window planner. Normal cores reserve 256 UTF-16 units on each side inside the existing 16,384-unit request limit. Only forced cuts inside a continuing sentence receive context. Whole Character boundaries and complete context words are retained. A finding belongs to the nonoverlapping core containing its original start offset, so overlap does not produce duplicate corrections. Normal sentence/paragraph cuts remain unchanged. Exceptional long words retain the previous 16,384-unit limit by using the original lossless splitter with the remaining context budget; they are not truncated to create space.

All requests still contain only the existing Markdown-safe projection, under the same captured server/consent. No public server, extra recipient, provider fallback, dependency, permission or configuration switch is added. Offsets, exact source/revision admission, cancellation, aggregate failure, incomplete-response rejection and the 5,000-finding bound remain enforced.
