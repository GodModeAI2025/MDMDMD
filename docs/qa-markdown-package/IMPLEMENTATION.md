# Lossless Markdown with referenced images

The previous MD action shared only a source file, while its explanatory text implied inserted images traveled with every format. MD still exports unchanged UTF-8 source; its UI now states that it does not contain image files. The new Markdown mit Bildern (ZIP) option packages the exact source and referenced original images. It exposes no theme controls because raw Markdown is not styled output. Title/author/language and chapter mapping are carried in a separate manifest, without rewriting source.

Single-page output has document.md, manifest.json, README.md and images at their unchanged relative Markdown paths. A manuscript has chapters/001/document.md, chapters/002/document.md, etc., with each chapter's original media paths inside its own folder. This preserves independent footnote/reference definitions, identical image names and unfinished code fences. It does not merge/reparse chapter sources into a synthetic document. Only selected writing-purpose chapters supplied by the existing manuscript picker are exported.

The pinned Swift Markdown AST identifies image uses, including reference-style images. Image syntax inside fenced/inline code does not collect assets. Repeated references within a chapter deduplicate the image; unreferenced attachments are not included. The supplied asset catalog remains the only source of bytes: no filesystem lookup or URL fetch occurs in the renderer. Missing/unsupported images fail the export rather than producing broken image placeholders.

Archive paths reject traversal, absolute/network paths, backslashes, controls, queries/fragments, colon stream names and encoded traversal. Reserved output names and case-insensitive collisions fail instead of overwriting the source/manifest on common extraction filesystems. Stored ZIP uses its existing CRC/UTF-8 path support. Source size is capped at 16 MiB per chapter, 1000 chapters and 512 MiB total raw entry bytes; the ZIP's own representability limits still apply. No original manuscript or media file is edited.

Raw HTML remains exactly in source, but HTML-only resource references are not gathered by the Markdown image walker; this produces a warning. Relative document links remain unchanged and their target documents are not automatically copied; this also produces a warning. A packaged manuscript's original inter-chapter relative links may require adjustment by the author. This is honest raw-source/media preservation, not a promise to replicate arbitrary linked filesystem contents or automatically publish a blog.
