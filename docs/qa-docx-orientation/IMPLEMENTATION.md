# Upright images in Word export

DOCXRenderer previously embedded original image bytes and computed the drawing extent from encoded pixel dimensions, without accounting for EXIF orientation. A camera photo stored as landscape pixels with portrait metadata consequently had landscape drawing geometry; its appearance also depended on the Word reader's EXIF policy.

DOCXImageOrientation normalizes only orientations 2–8 into an upright PNG export copy, using ImageIO orientation transformation at the original maximum pixel dimension. Orientations include mirrored cases. Orientation 1/absent remains byte-identical in its existing format. DOCXRenderer then computes the drawing extent from the normalized image and uses its PNG filename consistently in document/footnote relationships and media entries. Library/source ExportInput is a value copy and is not rewritten. Markdown packages, EPUB, HTML and blog export retain their previous original-byte policy.

The system operation uses kCGImageSourceCreateThumbnailFromImageAlways and kCGImageSourceCreateThumbnailWithTransform with maxPixelSize equal to the encoded longest edge; this requests full-resolution transformation rather than the editor's smaller preview. Apple's reference documents the transform's orientation/aspect-ratio behavior: https://developer.apple.com/documentation/imageio/kcgimagesourcecreatethumbnailwithtransform

Tests create an asymmetric four-color JPEG with explicit EXIF values 1–8. Independently decoded pixel corners are compared with fixed expected mappings; dimensions stay 80×40 or become 40×80. Upright JPEG remains byte-identical; transformed files are PNG. The source bytes remain unchanged. A separate Python zipfile/XML check validates actual archive CRC, PNG magic/path, image relationship and portrait drawing extent. Full suite 468 Swift Testing headline (three optional skips), 58 XCTest, no failures. Xcode MCP Build955 succeeds.

This is encoded artifact/pixel evidence, not a rendered Word/Pages reader test or physical-device proof. Full-resolution decoding can use substantial temporary memory within the existing 50-million-pixel admission limit; no memory/latency guarantee is made. PNG encoding and ImageIO decoding are synchronous and cancellation reaches their surrounding checkpoints. Unsupported orientation metadata fails rather than silently rotating incorrectly. No provisioning, sign/upload, original manuscript or account mutation occurs.
