# Private iCloud page resolution

The local merge contract now distinguishes an exact current version (`unchanged`) from an exact historical version (`historical`). A divergent received page is durably preserved in history and remains in the incoming queue. Repeating the receive no longer treats its historical copy as permission to acknowledge and discard the conflict input. The current library session retains both `conflictPreserved` and `historical` inputs until reconciliation.

The document core can prepare a local, remote or manually merged resolution as a new page revision. Preparation is read-only. Applying checks the exact original local page, rejects active edits/stale comparisons and retains both original versions. A merged Markdown choice preserves exact bytes and carries the union of known local/remote attachments. Library validation and image availability remain required. This local API does not prove CloudKit permissions; the runtime must admit the conflict against the active scope and current remote receipt.

The private library binding persists the selected remote base revision in its account/library checkpoint before committing the new local version. Projection of that resolution, including after a process restart, creates the outbound page payload based on the confirmed remote revision rather than the divergent previous local revision. Normal later edits made after an interrupted projection retain that server ancestry through the stored resolved revision's history. Partial enqueue/checkpoint failure keeps the reservation replayable; a reservation whose local document commit never occurred is retired by retry. Incoming adoption cannot silently erase a pending ancestry reservation.

## Review UI, runtime fencing and private recovery

The iCloud settings expose Seitenkonflikte prüfen. A selected private-page conflict opens local/iCloud/merged modes, native TextKit source panes, a page-property disclosure (location, tags, goal, purpose, favorite/trash state, rules/prompts and image names), private merge editing, explicit use/save and draft export. Merging retains local page properties and the current local/remote image union. Action rows adapt to narrow width; accessibility text sizes use a menu instead of segmented mode labels. A changed comparison requires reopening before another apply attempt.

Before document mutation, the session checks its active account/library scope, asks CloudKit for the current account and refreshes incoming changes without sending queued document edits. It requires the exact compared remote payload and exact local page bytes. The binding then commits the new page/outbox ancestry. Engine completion requires the same scope, latest remote input, intended queued revision and server base before removing that page's conflict inputs. Account/generation changes, active document edits, newer local/remote changes and uncertain queue persistence keep reconciliation pending. A known stale comparison leaves an otherwise active connection usable for reload. Other record kinds are not cleared by this page operation.

Repeated historical server inputs are moved to the end of the durable inbox rather than deduplicated in their older position, so a fetched return to an older version cannot be mistaken for a newer earlier input. Latest-input selection and restart behavior are covered by a native-record test.

Private review recovery is account/library/page-scoped, keyed by exact local and remote comparison digests and uses a distinct buffer UUID for every review window. Updating one window never overwrites another. The Entwürfe menu offers previews/dates from current and older comparisons; older text is restored only on explicit choice and forked into the current window. This restores text, not old page properties or an old grant. Files never enter sync records. Descriptor-based bounded enumeration/read/write rejects links, invalid identities, duplicate/unknown JSON fields and corrupt frames; an unreadable frame is retained and reported while valid other buffers stay available. Saving failure retains in-memory text and offers export; closing unsaved text requires an explicit destructive choice.

## Images referenced by an older merged draft

Merged Markdown now restores missing attachment metadata for actual media references from the same page's historical versions. The existing Markdown inventory parser excludes code and raw HTML examples. Metadata from unrelated pages is never borrowed automatically. Each referenced image must have its validated local bytes; missing files or conflicting byte-exact descriptors reject preparation without changing the library. Current local/remote attachment descriptors are also compared as exact encoded bytes, so Unicode-equivalent filenames cannot conceal conflicting metadata.
