# Keep writing review busy until cancellation settles

WritingQualitySheet.Stoppen previously invalidated the generation and immediately set checking=false. The cancelled task could still be finishing synchronous Markdown preparation, so another review could begin before the previous task returned. The result generation guard protected source mutation, but it did not prevent overlapping review work from repeated start/stop.

Stoppen now sets stopping=true and cancels the owned task without releasing its generation or busy admission. The main check button/settings/correction controls remain disabled while checking is true. A defer on each owned review/catalog task clears the busy/stopping/task state only after that task returns and only for the matching generation. Cancellation is not presented as a service error. Actual cancellation sets reviewCancelled and the settled empty-result view says Prüfung abgebrochen. Du kannst sie erneut starten. A new review clears prior findings/completion/cancelled state, and dictionary/engine changes clear the presentation state.

Disappearance/AI handoff still invalidate the generation before cancellation so old results cannot affect the departed view. This is per-sheet admission, not a process-wide concurrency limit across independent windows. The system Markdown/grammar work remains cooperative, and a synchronous step can finish before its cancellation check. No hard abort or millisecond latency claim.

Xcode MCP Build1018 compiles final source. The underlying module and its 473-test package suite from qa-quality-preparation are unchanged; this presentation/lifecycle-only fix uses native action evidence rather than a mirror state test. The previous long-review stop attempt is retained in qa-quality-preparation as unverified because it completed before the tap. This new native/ evidence must distinguish actual cancellation from normal completion. No source/profile/account/provider/cloud/upload changes are made by the test.
