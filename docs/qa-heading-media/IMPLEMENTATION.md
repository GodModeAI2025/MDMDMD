# Headings followed by media — 2026-10-11

The before regression reproduces an orphaned heading before an image, an image-first mixed paragraph and a table in tagged/plain output (14 expectation issues). Semantic traversal now defers a text-only heading chain until the following image/table geometry is known. Text-first mixed paragraphs also reserve their actual leading text fragment. No block is consumed or dropped by lookahead.

Images reserve the final heading and raster together. Large images fit proportionally within the page height left by the final complete heading; natural 96dpi size and original asset remain unchanged when they fit. Long heading chains still split between complete headings. For tables, measured header and first row/first fragment reserve together with the heading. A first tall row may begin with a partial fragment beneath the heading and continue with repeated artifact headers on later pages. The minimum aligned first line must fit; impossible unbreakable geometry fails explicitly. Intro headings attach outside Table; a candidate nested H1 inside Table was caught by independent-reader parent assertions and corrected before commit.

Validation: 606 Swift Testing headline, three optional skips and 58 XCTest pass. Tests cover ordinary image/table and mixed flow in both tag modes, a 30-heading chain before a full-page image, and 100-line first table-row continuations with all Unicode foxes retained. Actual independent strict pypdf reads six before/after pairs: heading moves from page 1 to page 2 with media, source text/Unicode retained (reader whitespace normalized), original 400x600 raster draw and link on heading page, table heading parent/rows correct, zero reader warnings.

Visual evidence has a material limit: Poppler renders ordinary image heading correctly but omits the heading before a table, although its content stream, font subset, pypdf extraction and Apple PDFKit rendering contain it. This is an unresolved reader-fidelity discrepancy; no upstream cause is established. Tagged/plain pixel parity across six pages also shares that omission, so parity alone is not visual-correctness proof. Retained visual-table-page-2.png captures the discrepancy; visual-table-pdfkit-page-2.png confirms Apple PDFKit shows a readable heading and unclipped table. Image-page-2 was visually reviewed: heading and proportionally correct raster fit within margins. The mixed emoji was present; the reader inserted whitespace rather than losing a character.

This scope does not cover image-containing headings, headings before nested list/quote/TOC/rule blocks, full reader/theme/manuscript/accessibility acceptance, or native iOS UI. The semantic app backend remains Debug QA only; Release uses WebKit. CloudKit/Push provisioning, signing, current-source upload and TestFlight installation remain open. No capabilities or runtime release gates changed.
