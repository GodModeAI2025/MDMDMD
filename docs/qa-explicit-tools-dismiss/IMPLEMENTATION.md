# Close the page-tools sheet through its owner

2026-10-10. Previous native flow saved table and rules, but the outer manuscript editor unexpectedly disappeared before the next text input was stored. The exact cause was not established; reopening and refocusing recovered normal writing, but did not prove an uninterrupted return from the rules sheet.

`PageToolsSheet` now requires an explicit `closed` callback. Its Save and Close actions call that callback, and `PageWritingView` changes only its own `tools` presentation Boolean. It no longer issues a general environment `dismiss` from that sheet after publishing the saved page. Existing synchronous mutation admission, revision/source checks, generation fences and failure handling are unchanged.

DEBUG-only traces distinguish `PAGE_TOOLS_REQUEST_CLOSE` from the isolated host's `QA_EDITOR_CLOSE_BUTTON` and `QA_EDITOR_PRESENTATION` transitions. No interactive-dismiss suppression, backend writes or focus workaround was added. These traces are absent from the optimized Release executable.

Xcode MCP Build683 succeeds with no errors. Optimized unsigned iOS Release1.0.0(3) succeeds, executable SHA256 `0a09aa0f10cf3047a10168a8e01bbce6bdc4e3c00a2d40cefa4ca371665c06ce`. The model layer is unchanged from the previously passing430 SwiftTesting functions and58XCTest cases; no new Boolean-mirroring test was added. Native original-flow verification passes: the third suffix is accepted without refocus or reopen, the editor stays open, and the owning-tools close trace is not followed by an outer-editor close. That session later disappeared. A read-only inspection of its isolated persisted journal independently confirms all three suffixes, table 12, rules RULE-QA, 93 bytes and matching baseline revision; it does not claim final journal closure. Attaching to the existing app was unavailable: Home was visible and activation opened a different process. No default/production UI was edited. No current Scriptum crash report was found in the two checked report directories; this does not establish the termination cause.

A separate fresh native run proves two Saves and an unsaved Close/cancel, each followed by ordered paragraph input without refocus or reopen. All three tools-close traces occur while the outer editor remains open. The outer presentation changes to false only after the explicit QA editor close. The final UI readback confirms BASE-QAONE-QATWO-QATHREE-QA, table 1, saved rules RULE-TWO2, discarded DROP-QA, 94 bytes, two original block IDs and zero recoveries. A separate read-only final-snapshot check matches source SHA-256 `0fc3d086b2478a9a46a736f878cce0d17a050080b35cf967ac6f3afa6f894ab4` and sees no journal files after host inspection. This does not prove journal absence before that host initializer. All 314-file source manifests match before their sessions end.

The previously observed dialog-to-writing failure is resolved in the tested native iPhone simulator flows. The initial failure's exact mechanism is still unproven; explicit ownership plus matched original-flow and repeated Save/cancel observations support the scoped correction, not a universal claim across devices or every modal.

This change targets explicit dialog ownership; it does not prove the original failure was caused by environment dismissal. Native observations must establish what actually happened. Physical-device, accessibility, general multiwindow and new signed TestFlight delivery remain separate requirements.
