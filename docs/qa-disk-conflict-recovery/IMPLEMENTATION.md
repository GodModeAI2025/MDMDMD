# Physical disk conflicts, foreign editor journals and rescue export

The previous disk-version guard prevented stale library writes, but an already-loaded store could still ignore a foreign active editor journal because typing changes only the journal, not library.json. It could overwrite that journal's page and leave later recovery conflicted. New permanent tests reproduced this and two app-model losses: physical-conflict saves failed without preserving visible source, and finalization wrongly considered matching obsolete in-memory state already durable. The pre-fix run failed seven assertions.

Under the existing kernel lock, opening an editor now rejects any existing journal for that page. Library commits preserve the exact baseline of every foreign journal instead of changing/deleting its page; independent state may still change. Recovery explicitly allows only its own journal set, read under the same lock. Unchanged expired journals contain no accepted edits and no longer block a valid later external revision. A malformed non-directory journal path still allows the pre-existing direct-save navigation fallback when no journal can exist there.

WritingLibrary now recognizes revision/edit-in-progress conflicts in text, block and metadata save paths and force-preserves the submitted draft even if its obsolete in-memory snapshot matches. Finalization failures capture the known journal page with block IDs/order. The winning library is not overwritten; rejected navigation remains rejected. A successfully captured draft is announced under Wiederherstellungen with a reopen instruction; archive failures retain their actual failure message. Equal repeated block captures reuse their recovery record. Existing attachment preservation/readback requirements remain.

PageWritingView adds Entwurf als Markdown sichern to its existing menu when a save error exists. It uses the current page binding and existing temporary Markdown/share flow without calling finishTyping. This provides a rescue path when the normal export is gated by failed finalization. A model-level test proves exact newest submitted UTF8/CRLF bytes and that this export does not falsely clear the save error or overwrite the winner. It does not prove keyboard/IME state or actual share-controller behavior.

Evidence: all 556 Swift Testing headline tests pass (three existing optional skips), plus all 58 XCTest. These include new text, block identity/deduplication, failed archive, failed finalization, expired unchanged journal, foreign-lease and rescue-export regressions. The first foreign-journal change broke the legacy blocked-journal/direct-navigation fallback; the directory check was corrected and the existing test retained unchanged. Current unsigned Simulator Debug and iOS27 Release builds succeed with terminal0/BUILD SUCCEEDED (work/disk-conflict-compile.log, work/disk-conflict-release.log). Release binary receipt is retained.

The actual macOS27Core process helper was rebuilt: twenty two-process Space-writing trials each yield one commit/one conflict and preserve all prior state. An already-loaded peer then attempts to overwrite a live foreign journal and is rejected with editInProgress. SIGKILL of the exact journalized helper followed by a fresh process restores the368022byte Unicode/CRLF draft byte-for-byte, its original revision and all21Spaces. PROCESS_PROOF.json and the helper/harness record this separate host-level proof. Reproduction uses the same commands as qa-library-writer with this directory substituted.

Native QA was delegated under the device-interaction skill. Fresh read-only Xcode inspection still shows the obsolete NativePickerOwnedProxy dialog for PID24613, while CLI status now says Permission disabled and mcp-server not running. The agent changed no permission, created no bridge/session, installed nothing and interacted with no device. NATIVE_QA.json explicitly records the rescue action as unverified. The earlier auto-review rejection of dialog dismissal remains subject to the existing pending user question; no bypass was attempted.

Limits: complete native conflict/reopen/rescue, marked text, attachments on failure, Files coordination, uncooperative writers, legacy changed-journal conflicts, real CloudKit merges and physical-device/locked-device/power-loss acceptance remain open. Recovery is conservative and leaves other versions intact; it does not automatically merge or replace the store behind active sessions. No signed archive/upload/new TestFlight build. R03/R08 and all R01-R15 remain binding at their full scope.
