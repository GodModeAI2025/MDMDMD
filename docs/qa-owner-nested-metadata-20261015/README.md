# Owner metadata on nested shared pages — 15 October 2026

The owner-side metadata lookup had the same one-level assumption previously corrected for participant sends. Creating a comment or revision on a page below another shared page failed with `invalidRecord`, whether the hierarchy root was a page or Space. Even on direct Space children, new metadata attached to the Space root instead of its actual page. The permanent two-root regression fails before the correction in `red.log`. The separate first attempt in `sandbox-cache-failure.log` is a compiler-cache sandbox failure, not behavioral evidence.

The shared owner lookup now follows cached native parent links to the share root, with same-zone/canonical page-or-Space identities, no cycles, exact fetched identities and a 4,096-record bound. It fetches every intermediate record from the private database and checks library/kind/UUID/live operation, the exact parent chain, the same share, current owner role and private permission. Account, active engine, cancellation and unchanged cached request are checked across awaits as before. New comments/replies/revisions then parent their own page, preserving the hierarchy. Existing record parents and private pages retain their previous behavior. No new page/image is granted access by this change.
