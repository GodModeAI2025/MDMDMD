# Owner share recovery

Owner creation now requires a durable account/library-scoped receipt store. After preparation, the exact CKShare record ID and a digest of the authorized record hierarchy are persisted before dispatching the atomic server modification. Every returned save must confirm its expected record identity/type before the operation can become locally confirmed. No invitation URL, document content or cached participant permission is stored in this log.

A restart reuses that exact operation ID/share ID. The transport checks the active account, fetches the share and validates the owner's role, private-only access, root share reference, each selected record's type/identity/parent and the complete authorized hierarchy. Additional descendants are rejected instead of expanding the scope silently. If the original share is absent and the operation was unconfirmed, retry uses the original record ID with optimistic atomic saving. A previously confirmed but subsequently absent share requires explicit lifecycle reconciliation; it never silently creates a replacement.

The log is bounded to 4,096 operations. Its namespace hash uses deterministically encoded account/library identity, preserving exact Unicode bytes. Corrupt/unsupported records are rejected without replacement, using the existing descriptor-based no-follow, private-permission, atomic/fsync file writer.

Validation: four focused tests passed for restart/confirmation identity, changed-manifest refusal, distinct accounts/libraries (including Unicode-equivalent but byte-distinct account IDs), corruption preservation, explicit CKShare ID reuse and hierarchy validation. The broader iCloud/shared/draft selection passed **86 tests**. Xcode MCP `BuildProject` passed in 7.928 seconds, no errors (receipt 72). Logs in the task workspace: `work/owner-share-receipt-tests.log`, `work/owner-share-receipt-regression.log`, `work/shared-catalog-qa/owner-share-build.json`.

These tests exercise native CloudKit record preparation and local receipt/graph contracts, not a live server save or invitation. Owner creation still has no production UI caller. Before connecting Apple's sharing controller, serialize this transport with private synchronization, import confirmed server metadata into the engine without manufacturing document conflicts, handle stopped/deleted shares explicitly, and reconcile additions to an existing shared hierarchy. The provisioning gate remains disabled. Actual invitation delivery and participant collaboration remain required acceptance evidence.
