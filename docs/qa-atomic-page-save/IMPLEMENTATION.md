# Atomic editor page and assistant-configuration saves

WritingLibrary.update previously committed title, Markdown, favorite, tags, hierarchical trash, goal and purpose as separate operations. A later rejection could leave earlier fields durably changed while the UI reported save failure. Page/Space tools similarly saved rules before validating/saving prompts. Permanent model regressions demonstrated six failures: partial rename/trash, multiple durable publications/history entries, and persisted rules after an invalid prompt list.

The editor now submits those page fields to one Core operation. It validates the base revision, editing ownership, word goal and purpose/trash combination before publishing; reconciles source blocks only for actual Markdown changes; normalizes tags using the existing byte-sensitive policy; and includes trash/restore descendants in the same candidate. Only affected, changed pages receive a new revision and one historical baseline. One existing guarded library commit publishes the complete result, with no schema/identity/attachment/hierarchy relocation change. The original nil-purpose representation remains when its effective purpose is unchanged; existing goal clamping at the UI boundary is retained.

Page/Space assistant configuration now validates the entire prompt-ID set before assigning rules/prompts together. Page saves use the existing revision guard/history machinery; Space saves use one validated library commit. Equal retries create no additional publication or revision. Existing individual Core setters remain available for independent single-field operations, while the combined UI actions use the atomic APIs.

Evidence: all 561 Swift Testing headline tests pass with the three existing optional skips, and all 58 XCTest tests pass. New fixed regressions verify disk/snapshot rollback for invalid combined changes, a single publication/baseline for valid multi-field saves, no rules persistence on invalid page/Space prompts, a single parent/child trash commit, and no duplicate history on configuration retry. Existing disk-conflict, foreign-journal, Unicode/identity, provider/scheduling, export and recovery tests remain in the full run. Current unsigned Simulator Debug and iOS27 Release compilation both pass with terminal0/BUILD SUCCEEDED (work/atomic-page-compile.log, work/atomic-page-release.log). RELEASE_COMPILE.json records the final binary.

Limits: this proves the Core/model transaction boundary, not complete native controls, undo/redo, marked text, Files coordination, distributed CloudKit merging or physical-device acceptance. Existing full scopes remain binding; this does not close R03 merely by test count. Last native evidence had Xcode-MCP disabled and the obsolete access dialog still open; the pending dialog/capability decisions remain unanswered. No permission action, signed archive/upload or new TestFlight delivery occurred. R01-R15 remain open where their full acceptance is missing.
