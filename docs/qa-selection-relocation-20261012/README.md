# Source selection after structural block changes

The live native input frame deliberately retains its original syntax basis while typing. A paragraph typed into `# Foo` therefore still displays that raw native buffer, even though its canonical Markdown is now a heading. The old structural commit rebuilt the global selection from native body coordinates through the newly classified projection. The actual current frame maps selected “Foo” to source range2/3; canonical re-projection gives4/2, selecting “o” plus a newline.

The pre-fix calculation was extracted without changing its behavior and used by the actual production commit path. Five frame-lifecycle cases fail15 assertions for relocation/selected-text preservation before the fix. They cover heading, list, quote, checklist and decomposed Unicode/emoji.

The admitted commit now captures the previous source selection and relocates it by the active block ID when existing UTF-8 bytes are unchanged, including appended CR/LF block separators. A missing active identity clears selection. Other changed source or a source range crossing the block falls back to the existing canonical body-coordinate behavior; this scoped correction does not certify arbitrary external edits or complete selection affinity across content changes.

The initial correction passed 46 block-editor test headlines and the 659-headline full regression, but its native duplication check failed: a recreated heading text field selected only the final “o”. These earlier receipts are retained as intermediate evidence, not final acceptance.

The recreated field previously initialized its selection from the old visible-body coordinates. Its initializer now maps the requested Markdown source selection through the new input frame's projection, on both UIKit and AppKit. The extracted old initialization fails two assertions (“o” instead of “Foo”); after correction all 47 block-editor test headlines pass. Final full regression passes 660 Swift Testing headlines (four optional skips) and 58 XCTest with no failures; unsigned iPhoneOS Release succeeds. The recreated-field native check also failed on the actual last-block duplication: `BlockEditing.duplicating` appends separators to the original block and the existing coordinator rebases. This run is retained in `native-recreation-failure`.

Two additional tests use the actual duplication function from a no-trailing-newline block and the actual AppKit coordinator synchronization. Both fail before correction. The correction admits retained source offsets only for byte-identical existing prefixes with CR/LF-only appended separators and converts the existing native selection through source coordinates before rebasing. All 49 block-editor headlines pass. The separator-aware final full regression passes 662 Swift Testing headlines (four optional skips), 58 XCTest and unsigned iPhoneOS Release. Official Xcode MCP fresh-installs this exact revision without QA launch flags. A new regular synthetic page is typed from `Text` to `# Foo`, “Foo” is selected and duplicated exactly once. Before duplication the canonical block is `# Foo`; afterward the same original identity has `# Foo\n\n` and a separate duplicate. The stable screenshot preserves the full “Foo” highlight. All source hashes remain unchanged and EndSession confirms stopped, the original Xcode destination is restored and the owned bridge exits successfully. This proves the scoped visible-selection scenario, not a provider payload or arbitrary external-edit affinity. Native artifacts are in `native-final`. No provider request, account or permission change follows from these tests.
