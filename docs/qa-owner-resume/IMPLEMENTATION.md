# Remembered owned-library iCloud connection

Explicit activation now saves a bounded, device-local connection selection after the native engine validates the current account. The selection contains only schema, the exact fixed container, stable owned-library UUID, opaque account scope, enabled state and a revision UUID. It contains no manuscript, grant or provider credentials and resides outside the exported library package. Initial activation remains a person action. A fresh process/window resumes only a previously enabled selection behind the real provisioned gate; missing or disabled metadata causes no account lookup.

A returning scene creates/reuses the library session and its existing serialized foreground worker. Restoration reloads/validates the selection before looking up the native account, compares the actual account bytes, and checks the selection revision again before engine creation and after activation. A different account becomes accountChanged without creating an outbox/transport. Explicit account renewal is the only UI action that permits a new scope. Ordinary retries and share preparation preserve the existing account restriction.

Explicit disconnect writes a revision-bearing disabled marker before completing transport shutdown. Old activation attempts cannot match an absent/older/enabled selection after this marker is committed. Runtime cleanup for retry does not erase the saved choice. No manuscript, pending outbox, recovery journal or old-account checkpoint is deleted. A failed local disconnect write stops the current transport but exposes an error explaining that the next-start choice could not be saved. A user-visible reset action can repair a malformed local selection by writing a disabled marker; it does not erase documents.

The selection uses the existing owned POSIX storage helper: no-follow directory/file descriptors, UID/private-mode checks, bounded reads (4 KiB), temporary exclusive writes, fsync, rename and directory fsync. Missing metadata is not repaired/created during automatic lookup. A symlink selection is rejected; explicit reset replaces the symlink entry without writing through its target. This is local application intent, not a CloudKit ACL or cryptographic grant. MainActor serializes these application updates; no cross-process metadata-writer contract is claimed.

A live editor previously prevented binding setup because its in-memory snapshot can contain an unfinished draft. Binding initialization now reads and validates the durable library.json baseline, while keeping the existing editor/observer and incoming-mutation guards. Only saved bytes bootstrap the outbox. Later durable commits enter the queue through the existing observer. A genuinely empty new store can bootstrap an empty baseline; missing nonempty/corrupt durable data still fails rather than uploading the draft.
