# Owned-library foreground synchronization

The private-library session now uses the same serialized ICloudForegroundRefresh helper as shared documents. A new durable projection requests a debounced synchronization while the library has an active hosting scene. Opening/resuming an active scene requests a refresh only for an already initialized session; this does not silently activate CloudKit, choose an account, accept a share, or enter an AI executor. Successful explicit activation requests the initial upload. Disconnect/account recovery preserves its existing explicit activation requirements.

ICloudLibrarySyncBinding now distinguishes its existing changesQueued bookkeeping callback from newChangesQueued. The new callback fires only when durable projection adds entries. No-op retries and uncommitted editing drafts cannot repeatedly wake the network. The existing callback and checkpoint/error semantics are retained. Newly committed conflict resolutions also produce a projection hint. Cloud queue failures never roll back the locally saved manuscript.

The app reads the actual hosting UIWindowScene via the existing activity reader used by the local task runner. The DocumentGroupLaunchScene ancestor can report an inactive SwiftUI phase for an active hosted editor; a global first-window lookup would also misroute multiple windows. The reader is now reusable as WorkspaceSceneActivityReader, with an optional explicit teardown callback. The scheduling caller retains its behavior and nil teardown callback.

Each WritingLibrary has independent weak scene leases. Inactivation/removal of one window cannot pause another active window of the same library; independent libraries retain independent admission. Switching the view to a replacement library closes the old registration. A late teardown from an old library is rejected by actual object identity, so it cannot retire the new library's registration. Dismantling the reader invalidates queued UIKit publications before releasing its lease.

Automatic requests arriving while a manual synchronization/share/conflict operation is busy are coalesced for a successful successor. Failed transports retain their explicit recovery path, rather than continuously retrying a blocked outbox. All send/fetch/merge operations still pass through the existing account validation, exact owned scope, durable outbox, revision ancestry and conflict handling. No provisioning/profile/schema/capability was changed; the source iCloud gate remains false.

## Verification and limitations

The full test log reports 451 Swift Testing tests (3 optional tests skipped) and 58 XCTest tests with no failures. New tests use a real LibraryStore/outbox to verify new saved changes produce one wake-up, 40 no-op retries produce none, an unfinished Unicode draft stays out of the outbox, the saved payload preserves bytes/ancestry, and invalidation detaches the signal. Model tests verify weak lease ownership, two active-window admission, independent libraries, and a late detach against two real temporary WritingLibrary objects. They are not native two-window or real CloudKit tests.

Xcode MCP Build832 passes on the existing iOS 27 simulator. The initial Build828 targeted the currently selected physical iPhone von M and failed on the missing iCloud profile capability/container/entitlements (plus Xcode account/device-profile diagnostics). That failure is retained, not represented as device verification. The original destination is restored after the native session. The optimized unsigned Release receipt is a separate compilation check, not an archive or TestFlight upload.

The DEBUG --scriptum-owner-foreground-ui-qa fixture uses a unique temporary manuscript library and the real WritingWorkspace/editor. Its session remains unprovisioned; no fake account/grant or provider is supplied. The native/ report records actual activity traces, ordinary writing persistence and Home/resume behavior against unchanged sources. This does not prove cloud send/receive, physical-device cancellation, or multiple simultaneously active native windows.

Cloud activation is still process-local; reopening a process does not yet restore a saved opt-in connection. Persisted activation and safe account revalidation on launch remain required work, alongside real schema/provisioning, two-device sharing and new signed TestFlight delivery. This turn does not claim R08/R12 completion.

## Final cancellation correction after native observation

The native source manifest belongs to the UI run above, before the final network-error policy adjustment. UI, scene reader, editor and registration sources were not changed afterward. The new policy applies only inside a configured transport's synchronization catch path, which the unprovisioned native fixture cannot enter. The final full model tests and optimized Release compilation cover that adjustment; no current-source real CloudKit or post-adjustment physical UI proof is claimed.

An owner transport that remains active and current can return to ready after a recognized CancellationError or CKError.operationCancelled only when its own caller task was canceled. Generation is checked again after the actor status await. Shared synchronization requires an already-ready, account-current context and confirmed subscription before treating cancellation as a pause; a previously failed session cannot be upgraded by cancellation. Account/permission/network/zone/storage errors remain failures even if caller cancellation occurs concurrently. This preserves the queued documents while allowing the serialized foreground successor to refresh after a normal scene pause. The new error-matrix test checks both native cancellation forms and rejects masking genuine errors; actual CloudKit cancellation delivery remains unverified.
