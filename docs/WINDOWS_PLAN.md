# Explicit owned-library windows and cold restoration

Files → Neues Bibliotheksfenster uses supportsMultipleWindows and public typed openWindow. It first finishes/persists the current editor via the existing navigation guard. Each request carries a unique scene-request UUID, durable owned-library locator, runtime handoff identity and optional initial page UUID. Repeated requests open distinct scenes; page UUID never selects a library.

The Codable locator is either primary or imported UUID, with schema validation. It contains no absolute/relative path, URL, secret or remote authority. App startup constructs/registers one default facade; imported activation registers its owning facade. Windows/default retain active facades, and a weak per-locator cache reuses the exact live facade/store. Strong pending handoffs are bounded64 with five-minute expiry and cleanup. Cached/live resolution does not consume pending capacity. Claiming consumes only the pending handoff, not the durable locator.

Host resolves without consuming during construction; on appearance the pending handoff is claimed while scene-local State retains the facade. For a cold process, resolution derives only Documents/Skriptum or Documents/ScriptumLibraries/UUID. Existing library directory/library.json and relevant journal/recovery JSON paths must be nonsymlink, regular/type-correct and bounded before opening. Missing/corrupt/unsafe scopes fail closed, never create an empty library or fall back to another default. LibraryStore performs its existing validated journal recovery normally. A pending restored facade is retained until appearance so repeated SwiftUI construction cannot create a second store.

New/source windows own independent selection/history State and retain their facade if the app default changes after import. Imported windows with identical page IDs restore by distinct locators. A later restore reuses a live cache or opens the same validated scope, rather than treating a consumed handoff as lost authority.

Tests cover cold registry with different default and identical page IDs, exact live facade/store reuse, forged live identities, invalid locator/path input, missing/corrupt/symlink no-write failures, unique/bounded/expired pending requests, UTF8/CRLF and block-ID journal recovery/history, and active-journal reuse without reopening. Initial session-only cold regression failed; durable implementation passes focused tests and iOS27 simulator SDK build.

Native multi-window selection/conflicts/import isolation and actual process termination/reopen remain acceptance gates. File preflight plus opening is synchronous on MainActor; no claim of adversarial cross-process filesystem race prevention or very-large-library performance. Existing window values from the earlier locator-less prototype cannot identify their cold scope and fail closed. R10 remains open until native proof and remaining requirements are complete.
