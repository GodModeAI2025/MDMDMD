# Workspace HTTP gateway domain wave

Minimal Node24 built-in HTTP adapter over the verified relational WorkspaceStore. Default bind is127.0.0.1; other bind requires explicit deployment configuration, never an automatic public listener. Production TLS/verified identity gateway and session enrollment remain required; this wave has no login/dev-token fallback, vault enrollment, encryption keys or provider call.

Routes: GET /health and GET /ready; POST /libraries; POST /libraries/:library/spaces; GET/POST/PUT /libraries/:library/spaces/:space/pages/:page; PUT/DELETE /libraries/:library/memberships/:targetAccount, /libraries/:library/spaces/:space/memberships/:targetAccount, and /libraries/:library/spaces/:space/pages/:page/memberships/:targetAccount; POST /session/logout. Membership targetAccount path component is the account being managed, never caller authority. The PUT role payload must be owner/editor/viewer/none and authorization remains current DB session+effective ACL. No body user/account/actor/issuer role claims. No CORS/OPTIONS allow-all.

Strict wire boundary: path UUIDs/no query/fragment/percent aliases; Bearer opaque base64url token header only; JSON object unknown/duplicate keys rejected, exact route DTO fields, UTF8 fatal decoding, application/json only for mutations, no body for reads/logout/delete unless specified. Encrypted envelope uses canonical standard-base64 strings, existing bounds/registered key refs; no plaintext/key generation. PUT requires one quoted UUID If-Match; mismatch returns409 without losing bytes/history. Maximum header8KiB, body3MiB (fits bounded2MiB ciphertext base64), request/body/socket deadlines, bounded in-flight concurrency. Oversized chunk bodies return413 and close/drain without unbounded buffering.

Errors: unauthenticated401; unauthorized/missing private resource both404 to avoid existence oracles; malformed400, oversized413, unsupported media415, method405 with minimalAllow, conflict409; SQL nonce/foreign-key/check/serialization errors map to controlled conflict/invalid/unavailable responses with no SQL/constraint/query/token/ciphertext details. Health contains only status; readiness only boolean503/200, never DB/version/credentials. Logs only optional opaque request IDs/status, no content/headers.

Permanent test-first proof using actual loopback HTTP server and parent's dedicated PostgreSQL18.6: strict auth/media/JSON/base64/unknown-fields/path denial; owner create/read/CAS encrypted bytes, viewer denial indistinguishable from missing, conflicting/nonce writes preserve current/history; real logout revokes subsequent request; controlled oversized chunk body; redacted SQL error; expiry/namespace isolation; default noCORS. Old2unit+10SQLtests stay unchanged. Each HTTP fixture owns a uniquely created/advisory-locked schema and cleans only that schema. No production/native activation claim.
