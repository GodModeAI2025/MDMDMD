## What is implemented

Executable PostgreSQL18 migration creates relational accounts, opaque server sessions, libraries, Spaces, encrypted pages/revision history, hierarchical memberships, schedules/runs/reservations/results and content-free audit. Compound library/Space/page keys isolate identical page UUIDs in different libraries. Revision CAS and prior encrypted-source history write share one transaction. Ciphertext/nonce/digest/key-reference columns enforce bounded envelope structure; real encryption/decryption/key rotation belongs to an eventual verified vault adapter. Verification bytes are explicitly synthetic ciphertext, not evidence of production cryptography.

`WorkspaceStore` identity comes only from hashed-token `server_sessions` lookup with expiry/revocation. It never accepts a claimed account/role for authorization. Fresh session admission is rechecked after library lock waits. Every library-scoped operation and membership mutation uses the same library row lock and fresh inherited rank. Owner/editor/viewer ranks propagate through parent ceilings; explicit child overrides only restrict effective access. UUIDs normalize before override matching, so uppercase aliases cannot bypass lower overrides. Native untrusted Automerge ingress remains absent.

`migrate` validates exact schema migration checksum and does not erase/replace existing tables. An immutable server-managed key registry and shared nonce ledger protect current pages, archived envelopes and encrypted results. Library-bound registered references cannot be supplied from another library. Historical content retention never frees nonce claims. Migration2 seeds existing envelopes and fails atomically for conflicting usage. Same checked-out pg client owns BEGIN/COMMIT/ROLLBACK. No retries conceal conflicts or external side effects. This code currently serializes library operations conservatively; a measured concurrency optimization is a following change.

## Identity gateway (owned verification, not live Apple deployment)

The cohesive identity pipeline now requires configured signed native OIDC proof, one-use challenge/nonce/state, matching authorization-code redemption and durable encrypted grant retention before atomic account/session publication. Roles/email in JWTs confer no memberships. Only SHA256 opaque session digests and vault references enter SQL; raw ID/access/refresh tokens and private signing keys do not. Migration003 preserves001/002 checksums, uses exact C-collated issuer/subject identity, deliberately revokes legacy production sessions, and adds account epoch/disable/tombstone, shared rate/capacity, consent/event/compensation/audit and one-use reauthentication rows.

Configured incoming algorithm is RS256; outbound developer signing is delegated to the configured vault adapter. `jose6.2.12` is exact-pinned (registry integrity in lockfile). JWKS transport has configured URL only, normal TLS, manual redirect rejection,3s/64KiB streaming limit and32public RSA keys; resolver30s cooldown/10min cache. Token/revoke requests have5s/32KiB caps and enrollment10s cancellation. Test-only cache timings/trusted fixture CA cannot be enabled through production environment. Native/exchanged issuer/subject/scalar audience must match, with exact nonce digest and bounded safe dates. Notifications use a separate audience/iat/events contract; exp is validated if present and is not required. Current Apple `account-deleted` and documented legacy `account-delete` normalize after signature verification.

Production `npm run start` calls configuredIdentity and either remains identity-disabled or validates full immutable Apple configuration AND an administrator-owned vault adapter module. Missing fields, profile/consent IDs over128ASCII bytes, whitespace, unsupported algorithms/test mode, missing adapter/callable signClientSecret/retain/load/remove capability fail startup. There is no development token/key/vault fallback. The adapter path is never selected by a request/token and must be an absolute regular non-symlink file not writable by group/others. Actual Apple audience/team/key/capability/notification registration, production vault and TLS origin remain unprovisioned; no live Apple endpoints were called by this work.

New wire: POST /identity/challenges ->201 five challenge fields; POST /identity/enroll ->201 sessionToken/sessionID/accountID/expiresAt/**reauthenticationReceipt**; GET /session ->200 accountID/sessionID/expiresAt; POST /session/logout-all ->204; DELETE /account requires reauthenticationReceipt and retentionConfirmation=`preserve-owned-libraries`; signed POST /identity/apple/events ->204. Enrollment proof creates a five-minute one-use account-bound deletion receipt; native may conservatively expire it from request-start and keep it only in memory. Deletion tombstones/revokes sessions/queues issuer grant revocation while preserving owned libraries; it does not claim those libraries were deleted. Auth lock order is account -> session -> library. Logout does not cancel independent server tasks/API grants.

The configured CLI starts a bounded, non-overlapping persistent revocation queue pump (10jobs/30s default) and aborts/joins it during shutdown. Provider failure remains durable uncertain with at most3attempts and5minute retry spacing, requiring operator reconciliation thereafter. Opaque compensation references exist before issuer/vault calls, so failed finalization retains a recoverable orphan reference. All compensation rows are capped100k; completed job/revoked-reference metadata prune after30days. Source/history/library data are not part of this pruning.
